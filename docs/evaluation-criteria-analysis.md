# 기말 프로젝트 평가 기준 분석과 NextSlide 대응 계획

작성일: 2026-11-17. 출처: 강의자료 Lecture 17(Diffusion Models III)의 9~10쪽 “Final Project Evaluation Criteria”, “Creativity Evaluation”. 강의자료 원본은 저장소에 올리지 않았습니다.

## 1. 기준 요약

| 항목 | 상단 막대 | 표 | 보는 것 |
|---|---|---|---|
| 창의성·독창성 | 30 | 30 | 문제, 방법, 모델 조합이 남다른가? 기존 작업을 확장했는가? |
| 기술 이해 | 15 | **20** | 모델의 원리와 설계 선택을 정확히 설명하는가? |
| 구현 | **20** | 15 | 아이디어가 실제로 구현됐고 핵심 기능이 동작하는가? |
| 실험·분석 | **25** | 20 | 비교로 아이디어를 검증하고 성공·실패·한계를 분석했는가? |
| 발표·질의응답 | 10 | **15** | 아이디어와 결과를 명확히 전달하고 질문에 잘 답하는가? |

- **같은 쪽 안에서 배점이 서로 다릅니다.** 창의성 30점만 같고 나머지 네 항목은 다릅니다. 둘 다 합계는 100점입니다. 어느 쪽이 맞는지 교수님께 확인해야 합니다. 확인 전에는 항목마다 더 큰 값을 기준으로 준비합니다.
- 쪽 하단 문구: “새로운 아이디어만으로는 부족하다. **작은 규모라도 구현하고 효과를 검증하라.**”

창의성 30점의 세부 배점(10쪽):

| 세부 | 점수 | 내용 |
|---|---|---|
| 새로움·차별성 | 15 | 아이디어가 얼마나 새롭고 **기존 프로젝트와 어떻게 다른가** |
| 유용성·흥미 | 10 | 왜 중요한 문제인가 |
| 구체화 | 5 | 구체적 방법으로 얼마나 발전시켰나 |

창의성으로 인정하는 것: 새 모델 구조, **새 응용 문제**, **기존 방법의 새로운 조합**, **데이터·조건 설계**, **더 나은 생성 과정 또는 사용자 상호작용**. 단순 재현도 허용되지만 높은 점수를 받으려면 자기만의 확장이 있어야 합니다.

→ NextSlide는 새 모델 구조를 제외한 네 가지에 모두 해당합니다. 반대로 “API를 이어 붙인 것” 이상이라는 근거를 보여 주지 못하면 새로움 점수(15점)에서 손해를 봅니다.

## 2. 항목별 현황과 할 일

### 창의성 (30)

| 세부 | 현재 근거 | 부족한 점 → 할 일 |
|---|---|---|
| 새로움 15 | 강의 맥락을 조건으로 쓴 다음 장 생성 / 발표자 확인을 거친 공개 / 형태 자동 선택(그림·수식·텍스트·비교·표·그래프) / 그래프 수치는 서버가 계산(근거 없는 숫자 차단) / 텍스트 먼저, 그림은 나중에 | 비슷한 선행 사례(ZeroPrep: 발화 → 즉시 장면 표시)가 있습니다. **선행 사례 대비 차별점 표**를 발표 앞부분에 넣어야 합니다. 비교 자료: `docs/qa-supplement-plan.md` 2절 |
| 유용성 10 | 즉흥 설명, 질문 대응, 준비 부담 감소 | 실제 사용자 반응 근거가 없습니다. 짧은 사용 평가(동료 2~3명, 5분 시연 후 설문)를 하면 보강됩니다 |
| 구체화 5 | 동작하는 전체 시스템 | 충분합니다 |

**“조건 설계”로 설명하기**: 이 강의에서 다룬 조건부 생성(텍스트 조건, CFG)과 연결됩니다. NextSlide에서 조건은 사용자가 직접 쓴 프롬프트가 아닙니다. 강의 음성에서 자동으로 만든 *요청 + 최근 발화 + 이전 장*을 조건으로 씁니다. 이 점을 창의성의 중심 주장으로 삼을 수 있습니다.

### 기술 이해 (15~20)

- **위험**: 이미지·텍스트·STT 모두 외부 API라 내부 구조를 보여 줄 수 없습니다. `gpt-image-2`의 구조는 공개되지 않았으므로 “확산 모델이다”라고 단정하면 안 됩니다.
- **대응 1 — 강의 내용과 설계 선택 연결.** 31쪽 “그럴듯한 이미지도 프롬프트를 놓칠 수 있다”(개수, 공간 관계, 속성 결합 실패)는 NextSlide가 **글자·수식·표·그래프를 이미지 모델에 맡기지 않고 고정 컴포넌트로 그리는 이유**와 바로 이어집니다. 이미지 모델은 글자 없는 설명 그림만 맡습니다.
- **대응 2 — 설계 선택마다 근거 제시.**
  - 발화마다 LLM을 호출하지 않고 규칙 기반으로 감지하는 이유: 비용, 지연, 오작동
  - JSON 스키마를 엄격하게 지정한 구조화 출력, 생성된 HTML을 실행하지 않는 이유: 안전성, 일관된 화면
  - 이미지 품질을 low로 둔 이유: 지연과 비용
  - 그림을 기다리지 않고 넘기기: 이미지 생성이 가장 느린 구간이라서
  - 각 근거를 실측값과 함께 제시합니다.

### 구현 (15~20)

- 실제 API로 끝까지 동작합니다(음성 → 감지 → 기획 → 이미지 → 발표 화면·청중 화면).
- 백엔드 테스트 98개, mock과 실제 API 구분 표시, 세션 저장·재발표까지 갖췄습니다.
- **위험은 실시간 시연 실패**(네트워크, 마이크, API 지연)입니다. 녹화 백업 영상을 준비하고, mock 모드를 쓸 때는 화면에 MOCK임을 분명히 표시합니다.

### 실험·분석 (20~25) — **가장 큰 공백**

현재 있는 것:

- 요청 감지 평가 56/60(93.3%). 단, 규칙을 만든 사람이 쓴 사례라 낙관적입니다.
- 실제 API 지연은 단계별로 n=1입니다.
- 맥락 A/B 실험은 도구만 만들어 두었고 실행하지 않았습니다.
- 실패율은 측정하지 않았습니다.

평가 기준은 **비교로 검증**하라고 합니다. 기준선 대비 실험을 제안합니다.

| # | 비교 | 검증하는 주장 | 방법 | 예상 비용 |
|---|---|---|---|---|
| E1 | 요청만 vs 요청 + 강의 맥락 | 맥락 조건이 더 맞는 장을 만든다 (핵심) | 시나리오 12개, 순서를 섞어 블라인드로 평가자 2명 이상이 채점, 평가자 간 일치도 보고. 이미 만든 `eval/run_context_ab.py` 사용 | 텍스트만이면 약 $0.01, 그림 포함 약 $0.11 |
| E2 | 단순 키워드 vs 규칙 감지기 | 오작동을 줄이면서 요청은 놓치지 않는다 | 다른 사람이 쓴 평가 사례와 실제 STT 전사 추가, 10분 일반 강의 발화에서 잘못 생성된 건수 | 거의 0 (STT 무료 등급) |
| E3 | 그림을 기다림 vs 텍스트 먼저 | 넘길 수 있을 때까지의 시간이 줄어든다 | 실제 API n≥10, 중앙값과 p90 | 약 $0.05 |
| E4 | 이미지 모델에 수식·표를 그리게 함 vs 형태 자동 선택 + 고정 컴포넌트 | 31쪽의 실패 유형을 구조적으로 피한다 | 수식·표·그래프 요청 5개씩, 정확성을 눈으로 판정하고 실패 예시 수집 | 약 $0.1 |
| E5 | — | 실패와 한계 | STT 오인식, 감지 놓침, 형태 오선택, LaTeX 오류, 지연 초과를 유형별로 분류하고 예시 제시 | — |

모두 기존 키의 사용량 범위에서 합계 약 $1 미만으로 예상합니다. 실행 전에 비용을 다시 확인합니다.

### 발표·질의응답 (10~15)

- **NextSlide로 NextSlide를 발표**하면 시연이 곧 발표가 됩니다. 실패하면 백업 영상으로 넘어갑니다.
- 예상 질문:
  - API를 이어 붙인 것 아닌가?
  - ZeroPrep 같은 기존 도구와 무엇이 다른가?
  - 틀린 내용이 생성되면 어떻게 하는가?
  - 왜 LLM이 아니라 규칙으로 감지하는가?
  - 지연과 비용은 얼마인가?
  - 이미지 모델의 원리는 무엇인가?

## 3. 우선순위

1. 배점이 엇갈리는 부분을 교수님께 확인합니다.
2. E1, E3, E4를 실행하고 결과를 `docs/results.md`에 정리합니다. 실험 점수와 창의성 근거를 한 번에 얻습니다.
3. 선행 사례 대비 차별점 표와 “조건 설계” 관점의 설명을 만듭니다.
4. `docs/results.md`의 지난 내용을 고칩니다. “레이아웃 하나뿐”, “지연 미측정” 같은 서술이 현재 상태와 다릅니다.
5. E2, 사용 평가, 백업 영상, 예상 질문 답변을 준비합니다.
