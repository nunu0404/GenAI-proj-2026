# 고도화 방향: 학생 질문에 답하는 보충 슬라이드

작성일: 2026-11-05. 상태: **설계 제안 (구현 전, 사용자 결정 대기)**

## 1. 목표 시나리오

1. 학생이 묻습니다. “과적합이랑 데이터 누수는 뭐가 달라요?”
2. 강사가 말합니다. “방금 설명한 두 개념을 시험 문제에 비유해서 비교해줘.”
3. 강사는 바로 답을 시작합니다. 그동안 NextSlide는 **비교 그림과 설명 한 장**을 준비합니다.
4. 준비된 장은 **강사 화면에만** 먼저 보입니다. 강사가 내용을 확인한 뒤 필요한 순간에만 청중에게 보여 주고, 다 쓰면 원래 장으로 돌아갑니다.

**가치 판단 기준** (사용자 제시)

- ‘요청할 때만 생성’은 따라 하기 쉽습니다.
- 차별점은 두 가지입니다.
  - (a) “방금 설명한 두 개념”을 **정확히 연결**하는가
  - (b) 강사가 **설명을 이어 가는 동안 보여 줄 만한 한 장을 준비**하는가

### YouTube “ZeroPrep V2 - Live presentation with images and cards”

**제목만 확인했습니다.** 설명과 내용은 가져오지 못해서 분석에 넣지 않았습니다.

### 시사점

- ZeroPrep은 “말하면 화면이 따라온다”에 집중합니다. 화면은 즉시 바뀌고 발표자가 거르지 않습니다.
- 질문 대응에서는 오히려 **즉시 표시가 위험**합니다. 틀린 개념을 연결한 장이 바로 청중에게 보이기 때문입니다.
- 보충 슬라이드는 **근거 있는 연결 + 강사 확인 + 원할 때 표시**로 차별화합니다.

## 3. 설계

### 3-1. 흐름

```
[질문 모드 진입]  강사가 Q 키 (또는 “질문 받겠습니다” 같은 표현)
      │  이 모드에서만 시스템에 대한 명령형 요청(“~비교해줘”, “~그려줘”)을 받는다 → 일반 강의 중 오작동 방지
      ▼
[질문 확보]  ① 마이크에 들린 학생 질문  ② 강사가 되묻는 말(“과적합이랑 데이터 누수 차이요?”)  ③ 발표자 화면 입력칸
      ▼
[1단계: 지시어 연결]  약 1~2초, 저가 LLM 1회
      입력: 학생 질문 + 최근 N분 발화 + 최근 장 + 강사 지시
      출력: {concepts:[{name, evidence: "근거 원문", source: question|transcript|slide}], confidence, alternatives}
      → 강사 화면에 즉시 표시: “과적합 ↔ 데이터 누수로 이해했습니다 (근거: ‘…’)”, 낮은 확신이면 후보 버튼
      ▼
[2단계: 보충 장 기획]  연결된 개념으로 고정. 요청 형태(비유·비교) 반영
      텍스트(비교 카드 + 요약)는 약 5초 → 대기함에 먼저 표시
      비유 그림은 약 15~19초 뒤 도착 (실측: 이미지 14~19초)
      ▼
[보충 슬라이드 대기함]  메인 덱에 섞지 않는 별도 영역. 미리보기 / 수정 / 버리기
      ▼
[보여 주기]  S 키 → 청중 화면이 보충 장으로 바뀜. B 키 → 원래 보던 장으로 복귀. (선택) “덱에 추가”
```

### 3-2. 필요한 변경 (현재 코드 기준)

| 영역 | 변경 |
|---|---|
| 감지 (`detector.py`) | ‘질문 모드’ 상태와 보충 요청 패턴(“~비교해줘/정리해줘/그려줘/보여줘” + 지시어). 일반 모드에서는 지금처럼 “다음 슬라이드…”만 인식 |
| 지시어 연결 (새 단계) | 구조화 출력 `ReferenceResolution`. 근거 원문은 실제 맥락에 있는 문자열이어야 함(서버에서 포함 여부 검증 → 지어낸 근거 차단) |
| 기획 (`planner.py`) | 연결된 개념을 ‘확정 입력’으로 받아 비교·비유 장 구성. 새 레이아웃 **비교 + 비유 그림**(좌우 카드 + 하단 또는 측면 그림) |
| 작업·저장 | 슬라이드 `kind = main | supplement`. 보충 장은 덱 순서에 끼지 않음. 청중 화면은 `showing_supplement_id`가 있으면 그것을 표시 |
| 화면 | 발표자 화면·전체 화면 모두에 대기함과 연결 결과 표시, S/B 키. 청중 창은 보여 줄 때만 바뀜 |

### 3-3. 측정 (가치 검증)

| 지표 | 방법 | 판단 기준 (제안) |
|---|---|---|
| **지시어 연결 정확도** | Q&A 시나리오 15~20개에 정답 개념을 라벨링(“방금 설명한 두 개념”, “아까 그거”, “이 둘” 등). 실제 LLM으로 정답률 측정 (약 $0.01 미만) | 정답률 ≥ 90%, 근거 원문이 실제 맥락에 있음 100% |
| **준비 시간** | 지시 종료 → 연결 결과 표시 / 텍스트 준비 / 그림 준비 (서버 단조 시계) | 연결 ≤ 3초, 텍스트 ≤ 8초 (강사가 답을 시작하는 동안), 그림 ≤ 25초 |
| **쓸 만한 장 비율** | 강사(사용자)가 블라인드로 ‘그대로 보여 줄 수 있음 / 고쳐서 / 못 씀’ 평가 | 실제 사용자 평가 전에는 점수를 만들지 않음 |
| **오작동** | 일반 강의 발화에서 보충 요청이 잘못 감지되는 비율 | 질문 모드 밖에서는 0건 |

## 4. 위험과 한계

- **학생 질문 녹음**: 강의실 마이크는 학생 목소리를 잘 못 잡습니다. 강사가 질문을 되묻는 습관이나 입력칸이 현실적인 대안입니다.
- **지시어 모호성**: “방금 그거”가 여러 후보를 가리킬 수 있습니다. 낮은 확신이면 강사에게 후보를 고르게 합니다(자동 확정 금지).
- **그림 지연**: 비유 그림은 실측 14~19초가 걸립니다. 텍스트 장을 먼저 보여 주고 그림은 도착하면 덧붙이는 방식이 필요할 수 있습니다.
- **사실 정확성**: 두 개념의 차이 설명은 강의에서 말한 내용과 표준 정의에 근거해야 합니다. 근거 없는 설명은 금지하고, 확인 후 표시로 막습니다.
- **개인정보**: Gemini 무료 등급에서는 학생 질문 음성도 Google 제품 개선에 사용될 수 있습니다(현재 결정 사항).

## 5. 제안하는 첫 단계 (승인 시)

1. Q&A 평가 세트(15~20개, 정답 라벨)와 지시어 연결 단계를 먼저 만들고 실제 LLM으로 정답률을 측정합니다. 여기서 가치 여부를 판단합니다.
2. 정답률이 기준을 넘으면 질문 모드, 보충 대기함, S/B 키, 비교 + 비유 그림 레이아웃을 붙입니다.
