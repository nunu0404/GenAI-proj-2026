# 구조와 데이터 흐름

## 구성 요소

```
브라우저 (발표자 탭)                          서버 (FastAPI, 단일 프로세스)                       외부 API
┌───────────────────────┐  WS 바이너리       ┌─────────────────────────────────────┐
│ getUserMedia           │  PCM16 24kHz 100ms │ stt_stream: 형식 검증 → 서버 VAD    │  WS   ┌──────────────────┐
│ AudioWorklet           ├───────────────────▶│  (20ms RMS, 침묵 700ms → commit)    ├──────▶│ OpenAI Realtime  │
│  48k/44.1k → FIR → 24k │                    │  partial/final ◀────────────────────┤◀──────┤ 전사             │
│                        │  WS JSON 이벤트     │ runtime                              │       └──────────────────┘
│ Presenter (React)      │◀───────────────────┤  ├ detector (규칙, 구간 누적)          │
│  현재 장 / 다음 장 미리보기 │                    │  ├ 맥락 스냅샷 고정(90초·1500자 상한) │ HTTPS ┌──────────────────┐
│  자막 / 작업 / 로그       │  REST (조작)       │  ├ 작업자 1개 + 대기열 ≤3           ├──────▶│ Claude Messages  │
│                        ├───────────────────▶│  ├ planner → SlideSpec 검증           │       │ (구조화 출력)     │
└───────────────────────┘                    │  ├ 이미지 → 검증 → 파일 저장          │ HTTPS ┌──────────────────┐
┌───────────────────────┐  WS (필터링)       │  └ hub: 역할별 브로드캐스트           ├──────▶│ OpenAI Images    │
│ Audience (별도 창)       │◀───────────────────┤ db: SQLite + data/images/<세션>/    │       └──────────────────┘
└───────────────────────┘                    └─────────────────────────────────────┘
```

API 키는 서버 환경변수에만 있습니다. 브라우저는 서버의 WebSocket과 REST만 사용하고, `/api/config`에는 제공자 이름과 모델 ID만 들어 있습니다(키는 포함하지 않으며 테스트로 확인).

## 요청 한 건의 흐름

1. **오디오**: 워클릿이 장치 샘플레이트(보통 48kHz)의 입력을 63탭 Blackman 윈도우드-싱크 저역통과 필터에 통과시킨 뒤 24kHz로 선형 보간해 PCM16 100ms 청크로 보냅니다. 서버는 `mic_start`의 `sample_rate=24000, pcm_s16le, mono` 선언을 검증하고, 다르면 거부합니다(OpenAI 문서: `audio/pcm` 24kHz mono PCM16).
2. **VAD와 commit**: `gpt-live-transcribe`는 `server_vad`와 `semantic_vad`를 지원하지 않습니다(문서, `turn_detection: null`). 그래서 서버가 20ms RMS로 구간을 나눕니다.
   - 유성 프레임이 시작되면 오디오를 보관만 하고, 유성 누적이 `VAD_MIN_SPEECH_MS`(250ms) 이상일 때 보관분(프리롤 포함)을 STT로 보냅니다. 그 전에 침묵이 이어지면 버리므로, 짧은 잡음은 전송도 commit도 하지 않습니다.
   - 발화 중 침묵 700ms 또는 최대 12초에서 `input_audio_buffer.commit`을 보냅니다.
   - 마지막 유성 프레임의 도착 시각을 *VAD 추정 발화 종료*로 기록합니다.
   - STT는 `session.update` 후 서버의 `session.updated`(실제 반영된 설정)를 받고 그 설정을 검증한 뒤에만 ready가 됩니다. 거부나 시간 초과는 오류 상태로 표시합니다.
3. **전사 이벤트와 순서 보정**: `committed(item_id)`로 우리 VAD 구간과 `item_id`를 연결합니다. `delta`는 임시 자막으로만 씁니다. 구간 ID는 `c<연결번호>:<item_id>`이며, 같은 ID의 중복 완료 이벤트는 무시합니다.
   - 문서상 `completed`의 순서는 보장되지 않으므로, **commit 순서대로 보관했다가 앞 구간부터** 확정 발화로 저장하고 감지기에 넣습니다.
   - 앞 구간이 실패하면 건너뜁니다. 뒤 구간이 도착했는데 앞 구간이 3초 넘게 오지 않거나, 어떤 결과도 10초 넘게 오지 않아도 건너뜁니다.
   - 늦게 온 구간은 자막과 기록에만 남깁니다. 재연결로 잃은 구간은 즉시 실패로 처리합니다.
4. **감지(detector.py)**: 확정 구간을 버퍼에 누적하고 이어 붙인 텍스트에서 트리거(`다음 슬라이드/장/페이지`, `슬라이드를 만들어 주세요`)를 찾습니다.
   - 완료 표현(`설명하겠습니다`, `보여주세요`, `주제는 X입니다` 등)이 나오면 즉시 판단합니다.
   - 완료 표현 없이 `REQUEST_SILENCE_MS`(2.5초) 동안 침묵하면 그때 판단합니다. 임시 결과나 유성 프레임이 들어오면 침묵 타이머가 연장됩니다.
   - 부정(`만들지 마세요`), 인용(`…라고 말하면`, `예를 들어 …`), 장 넘김(`다음 슬라이드를 보시면`, `다음 장으로 넘어가`)은 생성하지 않습니다.
   - 주제가 지시어나 채움말뿐이거나, 문장이 끊겼거나, 요청 표현 없이 서술문으로 끝나면 **입력 보완(needs_input)**으로 표시합니다.
   - 중복 방지 키는 `첫 구간 ID@오프셋..마지막 구간 ID`입니다. 감지기 메모리와 DB UNIQUE 제약 두 곳에서 막습니다. 같은 확정 발화를 다시 받아도 한 번만 생성하고, 나중에 다른 발화로 같은 주제를 요청하면 새로 생성합니다.
5. **요청 확정 → 맥락 고정**: 요청 시작 구간 직전 90초의 확정 발화(최대 1500자, 최근 쪽을 남김), 같은 구간 안에서 트리거 앞에 있던 말, 현재 슬라이드 제목과 핵심 문장, 강의 제목, 청중을 `jobs.context`에 저장합니다. 이후 들어온 발화는 이 작업에 섞이지 않습니다.
6. **대기열**: 세션마다 작업자 1개가 작업을 하나씩 실행하고, 대기는 최대 3개입니다. 대기열이 가득 차면 `queue.rejected` 이벤트로 접수되지 않았음을 알립니다.
7. **기획(planner.py)**: Claude에 `output_config.format`(JSON 스키마)로 요청하고, 거절되면 서버 측 `fallbacks: "default"`를 사용합니다. 결과는 `SlideSpec`(Pydantic)으로 검증합니다. 제목은 40자 이하, 핵심 문장은 2~3개이고 각 70자 이하이며, `needs_clarification`과 `precision_warning` 필드가 있습니다. 검증에 실패하면 불릿이 4개 이상일 때만 국소적으로 잘라 내고, 그 외에는 오류 내용을 붙여 1회만 재요청합니다. 발화 텍스트는 데이터 태그 안에 넣고, 그 안의 지시를 따르지 말라는 규칙을 시스템 프롬프트에 둡니다.
8. **텍스트 먼저**: 기획이 끝나면 슬라이드 행을 `text_ready`로 만들어 발표자 미리보기에 표시합니다. 청중에게는 보내지 않습니다.
9. **이미지**: 고정 스타일 접두어와 `글자·숫자·라벨 금지` 접미어를 붙여 `gpt-image-2`(1536x864)로 생성합니다. 응답은 매직 바이트로 MIME을 확인하고, 크기·디코딩·해상도·비율(요청과 ±0.08 이내)을 검증합니다. 이미지 없음, 거절, base64 오류는 모두 실패로 처리합니다. 재시도는 시간 초과, 429, 5xx일 때만 `IMAGE_MAX_RETRIES`회까지 합니다.
10. **완료**: 슬라이드 갱신은 `update_slide_if_job_attempt`(작업이 취소되지 않았고 시도 번호가 같을 때만)로 처리합니다. 준비 완료 이벤트를 받은 시점부터 브라우저가 이미지를 그릴 때까지의 시간을 브라우저 시계로만 재서 서버에 기록합니다.

## 상태

작업: `queued → planning → text_ready → generating_image → ready`, 여기에 `failed`, `cancelled`, `needs_input`(대기열 미점유)이 더해집니다.
슬라이드 상태는 작업 상태를 따르며, **`ready`인 장만 이동 대상이고 청중에게 전송**됩니다.

- **현재 장과 생성 중인 장의 분리**: 현재 장은 `sessions.current_slide_id`이고 사용자의 이동 조작이나 자동 전환으로만 바뀝니다. 생성 결과는 새 슬라이드 행에만 기록합니다.
- **자동 전환**: 기본은 OFF입니다. `auto_advance`와 `presenting`(발표 중)이 모두 켜져 있고, 현재 장이 새 장 바로 앞의 준비된 장일 때만 넘어갑니다.
- **취소**: DB 상태를 먼저 `cancelled`로 바꾸고 취소 이벤트를 설정합니다. 진행 중인 외부 호출은 강제로 끊지 않고 백그라운드에서 끝나게 둔 뒤, 결과는 버리고 사용량만 `ignored_cancelled`로 기록합니다. 작업자는 기다리지 않고 다음 작업으로 넘어갑니다.
- **재시작**: 서버가 시작될 때 진행 중이던 작업을 `failed(interrupted)`로 바꿉니다. 텍스트 초안은 유지되며, 재시도하면 이미지만 다시 생성합니다.

## 이벤트 (WebSocket)

모든 이벤트에 `session_id`가 들어가고, 작업 관련 이벤트에는 `job_id`도 들어갑니다.

| 이벤트 | 발표자 | 청중 |
|---|---|---|
| `snapshot` | 전체 상태 | 세션 제목, 현재 장, 준비된 장만 |
| `slide.updated` | 모든 상태 | `ready`만 (그 외 상태는 `slide.removed`로 바꿔 전송) |
| `session.updated` | 전체 | 현재 장 ID |
| `transcript.partial/final`, `detector`, `job.updated`, `queue.rejected`, `stt.*` | 전송 | 전송하지 않음 |

## 시간 측정 원칙

- 서버 구간은 같은 프로세스의 `time.monotonic()` 차이로 잽니다. 기록 항목은 확정 STT 수신 → 요청 확정, 확정 → 텍스트 완료, 이미지 생성, 확정 → 준비 완료입니다.
- 브라우저 렌더링은 `performance.now()` 차이(브라우저 단일 시계)로만 재고, 서버 시계와 섞지 않습니다.
- **실제 발화 종료 시각은 알 수 없습니다.** 음성 경로에서는 서버 VAD가 추정한 종료 시각을 `vad_*`라는 별도 이름으로 기록하며, 이 값에는 브라우저→서버 전송 지연과 VAD 판단 방식의 오차가 포함됩니다. 텍스트 입력 경로에서는 계산 불가(값 없음)로 두고, 그 건수를 따로 보고합니다.
- 통계에는 n, 평균, 중앙값, p95, 최소, 최대를 넣습니다. 실패율은 `failed / (ready + failed)`이고, 취소와 입력 보완은 따로 셉니다.

## 저장

- `sessions`, `utterances`(확정 텍스트만, 원시 음성 없음), `slides`, `jobs`(맥락 스냅샷, 지표), `usage_log`(모델, 설정, 토큰, 이미지 수, 오디오 초, 비용 추정, 결과 구분)
- 이미지: `backend/data/images/<세션>/<슬라이드>_a<시도>.<ext>`. 경로 검증을 거친 `/images/…`로만 제공합니다.
- 웹 렌더링과 저장소는 같은 슬라이드 데이터(`title`, `bullets`, `image_url`, `image_alt`, `layout`, `status`)를 사용합니다.
